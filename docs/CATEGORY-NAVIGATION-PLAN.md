# خطة الشاشات السفلية وتصنيف الميزات والإضافات

> تاريخ الإعداد: 2026-11-04
> النطاق: تنقّل Dolphy + تصنيف كل الميزات المدمجة والإضافات المثبّتة والمستقبلية.
> الافتراض: «الشاشات السفلية» تعني وجهات تنقّل سفلية ثابتة (Bottom Navigation) لكل فئة، مع شاشة سفلية «المزيد» (Bottom Sheet) للفئات الزائدة. إن كان المقصود Bottom Sheets فقط، تُنفَّذ المراحل نفسها مع استبدال الوجهات بأوراق سفلية.

---

## 0. الهدف

تحويل الوظائف من قائمة واحدة طويلة تحتوي أقساماً غير متوازنة (Bluetooth / IR / «Прочее») إلى تصنيف احترافي واضح:

1. شريط سفلي ثابت بأربع فئات أساسية + «المزيد».
2. شاشة مستقلة لكل فئة، بداخلها أقسام فرعية ومنطق عرض موحّد.
3. تصنيف تلقائي لكل إضافة مثبّتة أو قادمة، مع إمكانية تصحيح يدوي دون فقدان أي بطاقة.
4. بحث شامل، مثبّتة (Pinned)، عدّادات، شارات Root/Shizuku وتحديثات.
5. توافق كامل مع المسارات القديمة والروابط العميقة وبيانات المستخدم الحالية.

**ثابت لا يُكسر:** كل وجهة (ميزة مدمجة أو بطاقة إضافة) تظهر مرة واحدة بالضبط في فئة واحدة، ولا تختفي أي بطاقة أبداً.

## 3. سياسة تصنيف الإضافات (المثبّتة والقادمة)

### 3.1 أولوية القرار

لكل بطاقة إضافة (`OtherCardContribution`) يُحسب التصنيف بالترتيب التالي، وأول نتيجة تفوز:

1. **تصحيح المستخدم** المحفوظ يدوياً (السحب إلى قسم أو اختيار فئة).
2. **حقل `category` في ميتاداتا الإضافة** (الإصدار الجديد من العقد).
3. **حقل `section`** الحالي بعد تطبيعه عبر خريطة aliases موسّعة.
4. **الاستدلال من القدرات/الوسوم** (`tags`, `capabilities`): مثل `ble` ⇒ BLUETOOTH، `http` ⇒ NETWORK، `ir` ⇒ INFRARED، `nfc` ⇒ NFC، `usb` ⇒ USB.
5. **الافتراضي**: `OTHER` (غير مصنّف) — لا تُخفى البطاقة.

### 3.2 عقد الإضافة v2

```text
# dolphy-plugin
id: my.plugin
name: My Plugin
version: 1.2
category: bluetooth        # اختياري، يُفضّل استخدامه
tags: ble, scanner         # اختياري للبحث والاستدلال
section: BLUETOOTH         # مدعوم للتوافق، يُهمل إن وُجد category
```

- `add_module(..., category="bluetooth")` يدعم إلى جانب `section` الحالي.
- `section` يبقى صالحاً ولا يكسر أي إضافة قائمة.
- أي قيمة غير معروفة تُعامل كفئة مخصصة تُعرض داخل «المزيد» تحت «فئات الإضافات»، ويمكن للمستخدم دمجها في فئة أساسية.
- تُحدَّث `docs/plugins.html` ومرجع API وقوالب الإضافة، مع تحذير في معاينة التثبيت عند غياب التصنيف.

### 3.3 قواعد عدم التكرار

- البطاقة الواحدة لها **فئة أساسية واحدة** فقط.
- يمكن أن تحمل وسوماً إضافية تظهر في البحث فقط، لا في أكثر من فئة.
- إذا تعارض `category` مع `section`، يفوز `category` ويُسجّل تحذير للمطوّر.
- فئات مخصصة متعددة تُرتَّب أبجدياً داخل «المزيد» أو حسب `order`.

### 3.4 الترحيل

- مفتاح التخصيص القديم `pluginId:screenId:title:section` يُقرأ مرة واحدة ويُحوَّل إلى `...:category`، مع الإبقاء على القديم للقراءة فقط.
- الأقسام القديمة `INFRARED/BLUETOOTH/OTHER/PLUGINS` تُطابَق مباشرة؛ `PLUGINS` ⇒ `OTHER` (أو فئة الإضافات) لأنها لم تكن تصنيفاً فعلياً.
- الاختبارات تثبت أن كل بطاقة قبل الترحيل موجودة بعده بنفس المسار.

## 4. تصميم الواجهة السفلية

### 4.1 الشريط السفلي

**5 خانات:** `Bluetooth` · `Wi‑Fi` · `IR` · `NFC` · **المزيد**

- الشريط ثابت بكامل العرض (كما هو الآن)، أيقونة + تسمية، حالة اختيار بلون `primaryFixed`.
- «المزيد» يفتح Bottom Sheet يحتوي:
  - الفئات: USB والعتاد، الوسائط والبث، أدوات النظام، غير مصنّف (إن وُجدت بطاقات).
  - فئات الإضافات المخصصة.
  - إدارة الإضافات، مركز الأذونات، الإعدادات، النسخ الاحتياطي/التشخيص (عند توفرهما).
- شارة صغيرة على «المزيد» بعدد الفئات/التحديثات المخفية (اختياري)، وشارة تحديث على مدير الإضافات.
- سبب 4+1 بدل 8: تجنّب ازدحام الشريط، والاحتفاظ بالوصول بضغطة واحدة للفئات الأكثر استخداماً. تُقاس الأرقام لاحقاً ويُعاد الترتيب.

### 4.2 شاشة الفئة

كل فئة شاشة مستقلة (`category/{id}`) تتضمن:

1. **رأس**: عنوان الفئة + أيقونة + عدّاد الميزات + أيقونة إعدادات.
2. **بحث محلي** داخل الفئة (وفلتر «مثبّتة»).
3. **المثبّتة** (Pinned) في الأعلى، مع إمكانية إزالة التثبيت من قائمة البطاقة.
4. **الأقسام الفرعية** كعناوين، والبطاقات داخل كل قسم (قائمة/شبكة حسب النمط الحالي).
5. **بطاقات الإضافات**: أيقونة الإضافة، شارة Root/Shizuku، شارة «إضافة»، وزر معلومات.
6. **حالة فارغة** واضحة: «لا توجد ميزات في هذه الفئة» + زر «إدارة الإضافات».
7. **السحب لإعادة الترتيب** داخل الفئة (يُعاد استخدام `PluginRegistry.moveCard` مع نوع الفئة).

### 4.3 البحث الشامل

- حقل بحث في أعلى كل شاشة فئة، ونتائج موحّدة عبر الفئات عند الكتابة (تظهر الفئة بجانب كل نتيجة).
- يطابق: العنوان، الوصف، الوسوم، اسم الإضافة، معرّف الفئة.
- عند فتح نتيجة من فئة أخرى، ينتقل إلى الشاشة الصحيحة ويُبرز البطاقة.

### 4.4 السلوك والتنقل

- `Back` يعيد إلى الفئة السابقة، و`Predictive Back` مدعوم.
- استعادة الحالة بعد قتل العملية: آخر فئة + موضع التمرير + نص البحث.
- روابط عميقة: `dolphy://category/bluetooth` و`category/{id}`، مع الحفاظ على مسارات الميزات الحالية.
- المسار القديم `other` يبقى ويعيد التوجيه إلى «المزيد/كل الميزات» لتفادي كسر أي رابط أو إضافة تستخدم `navigate_app("other")`.
- الإعدادات تبقى متاحة من أيقونة الرأس ومن «المزيد» (وليست فئة في الشريط).

### 4.5 الإتاحة والحركة

- تسميات `contentDescription` لكل أيقونة، وأحجام لمس ≥ 48dp.
- RTL كامل: ترتيب الشريط والأقسام، واتجاه أيقونات الأسهم.
- دعم تكبير الخط 200% دون اقتطاع.
- حركة انتقال زنبركية خفيفة بين الفئات، واحترام «تقليل الحركة».

## 5. المعمارية التقنية

### 5.1 ملفات جديدة

| الملف | المسؤولية |
|---|---|
| `feature/catalog/FeatureCategory.kt` | enum الفئات: id، route، icon، titleRes، order |
| `feature/catalog/FeatureItem.kt` | نموذج موحّد: category، subCategory، source، capabilities، keywords |
| `feature/catalog/FeatureCatalog.kt` | دمج المدمج + الإضافات، الفهرسة، البحث، الثوابت (بلا تكرار) |
| `feature/catalog/CategoryScreen.kt` | شاشة الفئة (رأس، بحث، أقسام، بطاقات) |
| `feature/catalog/CategoryBottomBar.kt` | الشريط السفلي + «المزيد» |
| `feature/catalog/MoreCategoriesSheet.kt` | ورقة الفئات المخفية والإدارات |
| `feature/catalog/FeatureCategoryPrefs.kt` | تصحيحات المستخدم والترحيل |

### 5.2 تعديلات قائمة

| الملف | التعديل |
|---|---|
| `FunctionCatalog.kt` | إضافة `category`/`subCategory`/`tags` لكل `FunctionDestination`، وإبقاء التوافق |
| `OtherScreen.kt` | تحويله إلى `CategoryScreen` قابل لإعادة الاستخدام أو إبقاؤه كـ«كل الميزات» |
| `MainActivity.kt` | مسارات `category/{id}`، الشريط الجديد، إعادة توجيه `other` |
| `plugin/model/PluginModels.kt` | `category` و`tags` في `PluginManifest` و`OtherCardContribution` |
| `plugin/PluginRegistry.kt` | فهرسة حسب الفئة، حفظ التصحيح، الترحيل |
| `PluginManager.parseManifest` + مسارات JS/Python | قراءة `category`/`tags` مع تحقق وتطبيع |
| `docs/plugins.html` + مرجع API | توثيق العقد v2 وأمثلة |
| `res/values*/strings.xml` | أسماء الفئات والأقسام الفرعية (ar/en/ru) |

### 5.3 تدفق البيانات

```
PluginRegistry.otherCards ─┐
FunctionCatalog (built-in) ─┼─► FeatureCatalog ─► FeatureIndex
FeatureCategoryPrefs ──────┘        │
                                    ├─► byCategory(id)
                                    ├─► search(query)
                                    └─► all (بلا تكرار)
```

- يُبنى الفهرس مرة واحدة لكل `revision` ويُشتق بـ`derivedStateOf`؛ لا حساب ثقيل في كل إعادة تركيب.
- بناء الفهرس خارج الخيط الرئيسي عند وجود عدد كبير من الإضافات، مع حالة تحميل.

### 5.4 الأداء

- شاشة الفئة تعرض فئتها فقط → تقليل عدد العناصر المركّبة.
- مفاتيح Lazy صحيحة، وتجنّب `remember` غير المفتاحي.
- انتقال الفئة ≤ 300ms على جهاز متوسط.
- قياس jank قبل/بعد ونشره في تقرير الأداء.

## 6. خطة التنفيذ المرحلية

### المرحلة P0 — التصنيف والفهرس (1–2 أسبوع)

**المهام**
- إضافة `FeatureCategory` و`FeatureItem` و`FeatureCatalog` مع خريطة كاملة للميزات الـ20 الحالية.
- إضافة `category`/`tags` إلى `PluginManifest` و`OtherCardContribution` مع قيم افتراضية.
- توسيع `OtherSections.normalize`: wifi/network/nfc/usb/media/system/ar/en aliases.
- اختبار ثابت: كل وجهة مدمجة + كل بطاقة إضافة تظهر مرة واحدة، ولا بطاقة مفقودة.
- ترحيل مفاتيح التخصيص القديمة واختباره.

**القبول**: 100% من الميزات مصنّفة، 0 تكرار، 0 فقدان، الاختبارات خضراء، لا تغيير مرئي بعد.

### المرحلة P1 — الشريط والشاشات (2–3 أسابيع)

**المهام**
- الشريط السفلي 4+«المزيد» مع ورقة الفئات.
- `CategoryScreen` بالرأس والبحث والمثبّتة والأقسام الفرعية.
- مسارات `category/{id}` + إعادة توجيه `other` + الروابط العميقة.
- شارة العدّاد وتحديث الشارات (Root/Shizuku/إضافة).

**القبول**: كل فئة تُفتح من الشريط، وكل ميزة تصل إليها بضغطتين كحد أقصى، والرجوع سليم، والحالة تُستعاد بعد قتل العملية.

### المرحلة P2 — البحث والإدارة (2–3 أسابيع)

**المهام**
- بحث شامل موحّد مع إبراز النتائج والانتقال للفئة.
- إعادة ترتيب/تثبيت داخل الفئة، وسحب البطاقات بين الفئات للمستخدم.
- شاشة «غير مصنّف» + اقتراح تصنيف تلقائي لكل بطاقة.
- Empty states ورسائل إرشادية.

**القبول**: البحث يعيد نتائج من كل الفئات، ولا توجد بطاقة يتيمة، وتصحيح المستخدم يبقى بعد إعادة التشغيل.

### المرحلة P3 — عقد الإضافات v2 (2–3 أسابيع)

**المهام**
- دعم `category` و`tags` في الميتاداتا و`add_module`.
- تحقق وتطبيع + تحذيرات في معاينة التثبيت ومدير الإضافات.
- تحديث مرجع API والموقع وقالب الإضافة.
- اختبارات توافق: إضافة v1 بلا category تعمل وتُصنَّف بالاستدلال.

**القبول**: كل الإضافات الحالية تعمل دون تعديل، والإضافات الجديدة تُصنَّف تلقائياً، ولا كسر في التثبيت/التحديث.

### المرحلة P4 — الصقل والقياس (1–2 أسبوع)

**المهام**
- إتاحة كاملة (TalkBack، RTL، خط 200%، تقليل الحركة).
- قياس: زمن الوصول للميزة، عدد النقرات، استخدام البحث، jank الانتقال.
- ضبط ترتيب الشريط بناءً على الاستخدام (مع بقاء 4 فئات أساسية).
- تحديث `CHANGELOG` و`docs/ARCHITECTURE.md` و`DOLPHY-STATUS.md`.

**القبول**: 0 مشكلة إتاحة حرجة، KPIs موثّقة قبل/بعد، ورضا استخدام مُقاس.

## 7. الاختبارات

| النوع | التغطية |
|---|---|
| وحدة | خريطة كل ميزة، أولوية التصنيف، الترحيل، البحث، منع التكرار |
| تكامل | `PluginRegistry` + `FeatureCatalog` مع إضافات وهمية v1/v2 |
| Compose UI | تبديل الفئات، فتح «المزيد»، البحث، الرجوع، استعادة الحالة |
| أجهزة | RTL، خط 200%، TalkBack، أداء الفتح |
| انحدار | كل مسار قديم ما زال يعمل (روابط عميقة + `navigate_app`) |

**بوابات القبول**
- اختبار «لا بطاقة مفقودة/مكررة» إلزامي في CI.
- أي إضافة جديدة بلا تصنيف تظهر في «غير مصنّف» ولا تُسقط الاختبار.
- لا زيادة في زمن بدء التطبيق > 5%.

## 8. المخاطر والتخفيف

| المخاطرة | الأثر | التخفيف |
|---|---|---|
| ازدحام الشريط بكثرة الفئات | متوسط | 4+«المزيد»، وقياس الاستخدام قبل التوسيع |
| إضافات بلا تصنيف | منخفض | «غير مصنّف» + استدلال + تصحيح المستخدم |
| كسر التخصيص القديم | متوسط | ترحيل بمفتاح جديد وقراءة القديم كاحتياط |
| تكرار بطاقة بين فئتين | مرتفع | فئة أساسية واحدة + اختبار ثابت |
| كسر الروابط العميقة | متوسط | إبقاء `other` وإعادة التوجيه + اختبارات مسارات |
| أداء بناء الفهرس | متوسط | تخزين مؤقت حسب `revision` + حساب خارج الخيط |
| مقاومة المطوّرين للعقد الجديد | منخفض | `section` يبقى مدعوماً + توثيق وأمثلة |
